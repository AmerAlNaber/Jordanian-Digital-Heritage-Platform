# Changelog

All notable changes to this project are documented in this file. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Versions follow Semantic Versioning once the first release is tagged. Entries reference requirement identifiers from `SPEC.md` where they apply.

## [Unreleased]

### Added

- End-to-end suite (`tests/e2e`, Phase 1 gate, ACX-1): Playwright against the Compose stack in Arabic and English, light and dark, with axe on every page it visits. It registers a member in the interface language, verifies the email from Mailpit and chooses the password afterwards, verifies a phone with the code the mock SMS adapter logged, finds the seed book by a word from its scanned text, reads it through the gateway and prints two pages as a PDF, then signs a rights officer in (enrolling a one-time code on the way), finds every one of those actions in the audit viewer and takes a signed CSV export. CI runs it after the seed ingest and uploads the report and traces when it fails.
- Audit (ADM-5, SEC-25): `GET /audit/export` returns the matching events in chain order as CSV (UTF-8 with byte-order mark) or JSON, each record with its chain hashes, signed with an Ed25519 key derived from the token signing secret; the `Digest`, `X-Jdhp-Signature` and `X-Jdhp-Signature-Key` headers and `GET /audit/export/key` let an officer verify a file offline, an export that would exceed the row limit is refused rather than truncated, and every export is itself an audit event with its digest. The worker ships each day's events, signed, with a manifest of the chain boundaries to the object-locked archive bucket at 02:30 UTC (`jdhp.audit.ship`) and records the shipment in the log. The web application gains the staff audit viewer at `/staff/audit`: filters by user, action, resource and UTC time window, a paged table, the chain verification state, and the signed CSV and JSON exports with their key through the backend-for-frontend, which hands the signature headers through with the file.
- Accounts API (ACC-1, SEC-4, SEC-5, ADR-0009): `POST /me/phone` sends a six-digit code to a number in E.164 form through the SMS adapter (mock recorded locally; a real gateway is a Phase 2 adapter), three sends an hour and a minute apart; `POST /me/phone/verify` accepts it within ten minutes and five attempts, every refusal reads the same, the code is stored only as a keyed hash, and a verified phone raises the member to the `phone` level even when later tokens say nothing about it. `GET /me/sessions` lists the member's open readers with the sign-in each belongs to; `DELETE /me/sessions/{name}` ends one and `DELETE /me/sign-ins/{sid}` ends every reader of a sign-in, both within the cache window. Reader sessions record the identity provider's session id (migration 0005, with the `phone_verification` table under row-level security). The account page gains the phone step (number, then code, with the number always masked), and a list of every sign-in from the identity provider's account API with the readers open under each, where the member can end a sign-in or a single reader (SEC-5); the web application ends the sign-in at the identity provider with the member's own token and the readers through the API.
- Accounts (ACC-1, ACC-2, SEC-3, SEC-4, ADR-0009): the Keycloak image is now built from `infra/keycloak` with the platform's own extension, a `breachedPassword(n)` password policy that checks every new password against a k-anonymity range API (fails open with a warning by default, `JDHP_BREACHED_PASSWORD_FAIL_CLOSED` refuses instead) with unit tests against a local stub; the realm turns it on, verifies email at registration, and offers passkeys to members (resident, user-verified WebAuthn) while every staff role presents a one-time code (enrolling at first sign-in) and platform admins a hardware key as well; the browser flow asks for the username first, then a passkey or a password in a required step, then the second factors, and every step carries an `amr` reference so the API's `mfa` attribute is real. Registration asks for name and email and the password is chosen after the address is verified. The web application links to registration (`prompt=create`) and starts Keycloak's authenticator-app, passkey and password screens from the account page as application-initiated actions, in the page's language; member tokens carry the `account` audience for the session list to come (SEC-5).
- Web: the secure reader at `/read/{work}` (OpenSeadragon on the authorizing tile gateway, the tile token sent as a header and refreshed by the heartbeat, page and spread navigation that follows the book's direction, zoom, rotation, contents from section titles, in-book search drawn as boxes on the scan, citation, a print dialog that follows the job to its single-use link, keyboard operation, and a blank with the reason when the session ends) (RDR-1, RDR-3, RDR-4, RDR-5); the unified search page with facets and page hits that open the reader at the page; subject, place and period pages lead to the works about each term (CAT-2); page thumbnails and the cover come through the gateway for sample pages; a backend-for-frontend adds the member's token to the calls that act as them (ADR-0002). The tile gateway accepts the token in the `X-Jdhp-Tile` header as well as the query; `GET /search` without a query lists what the facets select.
- Print (`reader` module, RDR-4): a member with an open reader session asks for pages; the request is checked against the grant's page range and print quota, logged with the page numbers, and rendered by a worker from the access derivative at 150 ppi with the reader's visible mark (user, grant, work, time) and the session's forensic mark on every page (SEC-11). The PDF is written by the platform's own minimal writer (one JPEG per page, no text layer) into the exports bucket; the owner mints a download link whose token is hashed, lives fifteen minutes and works once, and the file is deleted on delivery (SEC-15). Quota is counted from the jobs themselves, so a failed render gives its pages back. Print jobs carry opaque names (migration 0004) and a Cerbos `print_job` policy; the work policy now lets only grant holders print, since the grant carries the quota (ADR-0008).
- Search (`search` module, `GET /search`): one query over work metadata and page text, Arabic-aware (diacritics, hamza and ta marbuta folded, ICU tokens, stemming) with a Latin analyzer beside it; the query and its vocabulary and agent-name expansions are fused by reciprocal rank fusion; facets for subject, place, period, language and access class; scope to one collection or one work. Every hit is rechecked against the database under the caller's visibility and the mandatory filters sit inside every index query, so drafts, embargoed and frozen works never reach hits or facets (CAT-5). A page hit is a sequence number, a score and word boxes on the scan, computed from term-vector offsets and the ALTO offsets map; boxes are given only for pages whose scan the caller may see, and no text, snippet or highlight ever leaves the index (CAT-4, SRCH-1 to SRCH-4). An in-memory twin of the OpenSearch backend serves the tests; the Compose job searches the seed book through the real stack.
- Forensic mark (`apps/api/src/jdhp_api/modules/reader/forensic.py`, ADR-0006): a blind spread-spectrum mark in the block DCT of the luminance, seeded by the reader session's key, applied to every protected tile after the visible mark; detected with its key only, survives WebP and JPEG re-encoding and grayscale conversion; `python -m jdhp_worker.tools.detect_mark` is the staff detector (SEC-11, RDR-2).
- Tile gateway (`apps/api/tiles_app.py`, Compose service `tiles` behind Caddy's `/iiif/*`): IIIF Image API 3.0 `info.json` and tiles for every page, authorized by the policy engine per page with the decision cached per session for sixty seconds; the five-minute tile token is the only credential; the pixel area of a response is capped and `max` is refused for protected works; every protected tile carries the reader's mark (user tag, time, work, session) and every sample or open tile the platform mark; rate limits per user and per IP suspend the session with a high-severity audit event; Redis loss falls back to a fresh policy decision and an in-memory limiter, never to an open door (RDR-1, RDR-2, SEC-6, SEC-10, SEC-11, SEC-12, SEC-14). Two image sources behind one interface: the Cantaloupe proxy with the signed internal header, and a libvips source that crops the JPEG 2000 derivative itself (ADR-0005, proposed). The worker's sample mark now calls the same libvips implementation.
- Reader sessions (`apps/api`, `reader` module): opening a session binds a principal, a work, a grant and one device; the browser holds a ten-minute grant token (JWT, EdDSA) and a five-minute tile token (HMAC), both refreshed by a heartbeat that re-validates expiry, revocation and the device limit, records pages read and dwell time in the audit log, and blanks the reader with a localized reason when the session is over (SEC-2, SEC-10, RDR-5, RDR-6). Per-session forensic keys are derived and stored sealed (SEC-11). A IIIF Presentation 3 manifest per work points at the tile gateway, carries no text, and shows only the sample range without a grant token (RDR-1). ADR-0007 records the credential formats.
- Access (`access` module): grants implied by the Open and Registered classes are created on first read with a device limit and a print quota; members list their grants; rights officers revoke a grant and every reader on it loses access within the cache window (ACS-2, SEC-5). Grants and sessions carry opaque public names (INT-7). Cerbos `reader_session` policy with tests.
- `docs/decisions/ADR-0004-phase-0-closure.md`: the owner's decisions at the close of Phase 0 (ARK test number until handover, typefaces confirmed, image server decision folded into the tile gateway work, accepted advisories kept under review, pipeline failures recorded on the batch).
- `docs/decisions/ADR-0001-stack.md`: accepted record of the specified stack and the open decisions D1 to D17 (all defaults, repository name with `jdhp` as the technical short name, workers reuse the API package in-process).
- `docs/ARCHITECTURE.md`: architecture of the core layer derived from `SPEC.md`.
- `docs/THREAT_MODEL.md`: threat model derived from `SPEC.md`, covering SEC-1 to SEC-31, REV-1, RDR-1 and CAT-4 with the test that proves each control.
- `CHANGELOG.md`.
- API (`apps/api`): FastAPI modular monolith with configuration validated at startup (SEC-19), Keycloak token verification with the 10-minute lifetime enforced (SEC-1, SEC-2), the `Authorize` dependency that asks Cerbos on every route and fails closed (SEC-6, SEC-7), hash-chained append-only audit events (SEC-8), UUIDv7 keys and ARK identifiers (INT-7), catalog, identity, intake, content, review and audit routes, and the route-coverage test that fails on any unprotected route.
- Database: Alembic migrations for the Phase 0 schema with row-level security on every table that holds personal or access data, the review guard trigger that keeps AI objects `pending` until a Reviewer approves them in the portal (REV-1), and the audit trigger that forbids update and delete (SEC-8).
- Policies (`policies/`): Cerbos derived roles and resource policies for works, pages, content objects, review tasks, intake batches and audit, with 815 test cases covering every role and access class, including denials (SEC-6).
- Packages: `ai-adapters` with the OCR, language model and embedding interfaces and mock providers refused outside local and test (TRN-6); `metadata` with METS, ALTO and checksum builders behind hardened XML parsing.
- Seed: the fictional 40-page book, a renderer that produces 400 ppi masters with ground truth, and the pipeline that ingests it (ADM-1).
- Worker (`apps/worker`): Celery application and inline runner; intake validation, preservation write, METS and checksums, JP2/PTIF derivatives and marked samples (SEC-14), mock OCR to ALTO, page and work indexing (CAT-4), embeddings with model and version recorded (SRCH-6), fixity verification that freezes a work and opens an incident on mismatch (SEC-26).
- Infrastructure: Docker Compose stack for local and pilot with Caddy, Keycloak realm template and MFA flows (SEC-1 to SEC-4), Cerbos, PostgreSQL with pgvector, OpenSearch with the Arabic analyzer, Redis, MinIO with object lock, Cantaloupe behind an HMAC-authorizing delegate (SEC-10), Mailpit; `.env.example` documents every variable and `infra/compose/make-env.sh` generates local secrets; k3s skeleton under `infra/k8s`.
- Design (`packages/design-tokens`, `docs/DESIGN.md`): OKLCH tokens built to CSS variables and a Tailwind preset with contrast tests (ACX-4); typeface decision (INT-3).
- Web (`apps/web`, `packages/schemas`): Next.js 15 application with Arabic as the default locale, externalized strings (INT-1), logical properties and `dir` on every container (INT-2), locale numerals and Hijri dates (INT-4), per-request CSP nonces and security headers (SEC-16), `robots.txt` welcoming AI crawlers on open metadata (SEO-5), machine-readable citations and ARK resolution (SEO-7), and a BFF sign-in with PKCE and encrypted server-side sessions (SEC-1, SEC-2); catalog, collection, subject, record and account pages typed from the OpenAPI document.
- CI (`.github/workflows/ci.yml`): lint and type checks, API tests with the 80 percent coverage gate against real PostgreSQL, Redis and Cerbos, worker and policy tests, web tests and build, OpenAPI and generated-type sync checks, Semgrep, Bandit, pip-audit, npm audit, gitleaks, image builds scanned with Trivy (SEC-18, SEC-20), and the Compose integration job that brings up every service and ingests the seed book.
- `docs/COMPLIANCE_MATRIX.md` skeleton, `docs/operations/` runbooks, `tests/load` and `tests/search-eval` placeholders.

### Fixed

- Keycloak realm (SEC-1, SEC-3): importing the template into the real server found five defects the data-only tests had passed. The role condition used a key this Keycloak does not read, so staff MFA never applied; the `staff` composite pointed the wrong way, so no staff account held it; listing one client scope suppressed the built-in `profile`, `email`, `roles` and `basic` scopes, so a browser sign-in failed with `invalid_scope` and tokens carried no roles; the default role's composites were not imported, so new members held no `member` role; and the realm frontend URL lacked the `/auth` path, so every rendered link was wrong behind Caddy. Each fix has a realm test (ADR-0009).
- Compose and CI: the first tile through the Cantaloupe image source failed. Cantaloupe 5.0.7 builds its S3 client for a script lookup from the delegate's answer alone, so the delegate now returns the endpoint, region and credentials with the bucket and key; the server's own size list (`restrict_to_sizes`) refused every region tile the gateway asks for, so it is off and the gateway's `info.json` stays the one place that confines sizes and area (SEC-10); the delegate checks the gateway's signature before the source is touched and answers the metadata hook that Cantaloupe calls on every image request. The gateway answers an unreachable or failing image server with a 502 problem response and a log line instead of an unhandled exception (RDR-1).
- CI: the OpenAPI export job imports the API application without libvips, so the print service loads its libvips-backed modules only when a render runs; the tile check no longer pipes `curl` into an interpreter; migrations 0003 and 0004 backfill public names with SQLAlchemy core instead of SQL strings (Semgrep); Prettier formatting restored on the web sources and the Compose file.
- Web: the reader fetches each page's `info.json` itself with the tile token, so protected pages open; a session that resolves after the reader unmounted is closed at once; the development server's Content Security Policy allows `eval` for hot reloading (production never does); `JDHP_DEV_API_URL` and `JDHP_DEV_TILES_URL` proxy the API and tiles through the development server so the browser stays same-origin without Caddy (SEC-16).
- Web (SEC-1, ACX-1): the OpenID client discovers Keycloak through the internal address but Keycloak names the public issuer, and the library refused that document, so every sign-in and registration behind the edge failed with a server error. Discovery now fetches the metadata, checks the issuer is the configured public one and builds the client from it; a failed discovery is not cached. The search page's facet links no longer claim a button state and meet the target-size and contrast checks; the page grid on a record gives no ARIA name to tiles that are not links. The Keycloak login theme follows the browser's dark scheme with the platform palette, so its forms keep their contrast in dark mode.
- Tests: the tile rate-limit tests freeze the limiter's clock (now injectable) so the burst window cannot straddle a second boundary under load (SEC-12).
- Seed: the book is rendered in a fresh interpreter. Pillow's text layout is corrupted in any process where libvips has been loaded, and the API application now loads libvips at import for the print renderer, which broke the seed in the test session and would break the Compose seed command (ADM-1).
- Worker: a derivative, OCR, embedding or packaging failure now marks the intake batch `failed` with the page, stage and reason, and writes a PREMIS fail event, instead of leaving the batch in `validating` with no trace (ADM-1, ADR-0004).
- Worker: public sample derivatives failed inside the Celery prefork pool. Pillow's text layout returned a corrupt glyph run in forked worker processes once libvips was loaded, every sample page errored and the seed batch never reached `ingested`. The platform mark is now rendered by libvips, the library that writes the derivative, and a regression test renders it in a forked child (SEC-14).
- Worker: a digital object is marked `ingested` and committed before its work document is indexed, so a search-index failure no longer rolls the state back (CAT-4).
- Compose: the API and worker depend on the OpenSearch template init container completing, which is the order the pipeline needs and what lets `docker compose up --wait` accept the one-shot container exiting (SRC-1).
- CI: the Compose integration job reports page progress while it waits for the seed batch and prints the worker log when the wait times out.

### Security

- Keycloak moves from the floating `26.0` tag to a pinned `26.7.5` built in the repository and scanned with the other images; the login theme and the extension travel inside the image, and the image states its non-root user (SEC-18, SEC-20). One advisory is accepted in `.trivyignore`: CVE-2025-59250 names the bundled `mssql-jdbc` 13.2.1.jre11, which is the fixed release (Trivy ranks the version below its own `.jre11` suffix) and a driver the realm never loads, since it runs on PostgreSQL.
- Next.js pinned to 15.5.24 and transitive `postcss` and `sharp` raised through `pnpm.overrides` so `pnpm audit` passes at the high level (SEC-18). One advisory without a patched release, GHSA-vfj7-8cjw-p6xm in the development-only `braces` dependency of the Next.js ESLint plugin, is listed in `pnpm.auditConfig.ignoreGhsas` until a fix ships.
- Images apply the base distribution's security updates at build time, the web runtime image carries only Node.js (npm, corepack and yarn are removed with their bundled dependencies), and Trivy blocks any high or critical finding not accepted in `.trivyignore` with a written reason (SEC-18).
- MinIO withdrew its container images from the public registries, so the object store is built from the pinned MinIO and mc source releases in `infra/compose/minio` (ADR-0003), with the Go modules Trivy names raised to their fixed versions at build time; the image is scanned like every other.
- Cantaloupe moves to 5.0.7, the latest release. Its image is scanned for operating system packages only: the Java libraries bundled in the upstream release carry fixed vulnerabilities that cannot be replaced without rebuilding Cantaloupe from source. The Phase 1 tile gateway work decides between a source build with current dependencies and another IIIF server; until then the image is reachable only from the tile gateway on the internal network.
